# 搬瓦工丢包：先用 Ping 和 MTR 定位问题，再按线路和套餐做选择

搜索“搬瓦工丢包”的人，通常不是单纯想知道某个 VPS 的理论线路，而是遇到了几个很具体的问题：

- SSH 连接一会儿卡住，一会儿又恢复；
- 网站在国内访问时偶尔超时；
- Ping 显示丢包，但服务器本身负载并不高；
- 晚高峰延迟明显升高；
- 换了机房之后，速度和稳定性差异很大；
- 不确定到底是本地宽带、国际线路、机房，还是 VPS 配置本身出了问题。

搬瓦工的确提供不同网络等级和机房选择，但“买了 CN2 GIA 就永远不丢包”并不符合实际。丢包需要结合时间、运营商、去程和回程路线判断。一个节点在中国电信网络下表现不错，不代表中国联通、中国移动和所有地区都完全一样。

下面按排查顺序说明：如何确认搬瓦工丢包是否真实存在、怎么看 MTR、哪些情况属于中间节点不响应、什么时候应该迁移机房，以及不同套餐和线路应该怎么选。

## 搬瓦工丢包，先别急着换套餐

丢包不一定发生在 VPS 本身。

从本地电脑到海外 VPS，中间会经过家庭路由器、运营商城域网、国内骨干网、国际出口、海外运营商和数据中心网络。Ping 或 MTR 报告中某一跳显示 20% 丢包，只能说明这一跳没有完整回复测试包，不能直接证明最终连接真的丢了 20% 的数据。

更有参考价值的是：

1. 丢包是否从某一跳开始持续到最后一跳；
2. 最后一跳是否也出现明显丢包；
3. TCP 连接、SSH、网站访问是否同时受到影响；
4. 丢包是否只在晚高峰出现；
5. 电信、联通、移动网络是否表现一致。

搬瓦工官方对不同中国方向网络的说明也提到，普通 ChinaNet（AS4134）和 CN2 GT 在高峰期可能出现拥堵，而 CN2 GIA 和 CTGNet 的目标就是改善中国方向的网络质量。官方资料同时指出，CN2 GIA 成本更高、可用容量也更有限，因此它并不是一个能够消除所有网络问题的“防丢包开关”。

## 先判断：这是“假丢包”还是实际丢包

### 中间某一跳丢包，最后一跳正常

这是最常见的误判。

有些路由器会限制 ICMP 响应，或者降低对 traceroute、MTR 测试包的处理优先级。于是某一跳可能显示 30% 甚至更高的丢包，但后续节点和最终服务器仍然是 0% 丢包。

例如：

text
Host              Loss%   Snt   Last   Avg  Best  Wrst  StDev
10.0.0.1           0.0%   100    1.2   1.5   1.1   4.2   0.4
203.x.x.x         35.0%   100   80.1  82.4  78.2  95.7   3.8
192.x.x.x          0.0%   100   92.3  94.1  91.5 105.4   2.1
目标 VPS           0.0%   100   95.4  96.8  93.9 110.2   2.9


这种结果不能直接说明目标 VPS 丢包。中间节点可能只是“不愿意回答测试包”，但仍然正常转发流量。

判断时重点看最后一行。如果最后一跳稳定为 0%，且网站、SSH、文件传输都正常，中间节点的高 Loss 通常不用单独处理。

### 丢包从某一跳开始，并持续到最后一跳

这种情况更值得关注。

如果从某一跳开始出现 5% 到 10% 的丢包，后面每一跳直到目标 VPS 都保持类似比例，同时实际连接也会卡顿或断开，那么问题可能出现在：

- 本地宽带或 Wi-Fi；
- 国内运营商出口；
- 国际转接线路；
- VPS 所在机房的上游网络；
- 目标服务器网卡、宿主机或系统负载。

这时不要只截一张 MTR 图下结论。建议分别在工作日白天、晚高峰和周末测试，每次至少持续 5 到 10 分钟。单次测试只有几十个数据包，偶然波动很容易被误判成长期故障。

### Ping 丢包，但网页和 SSH 正常

如果 Ping 显示少量丢包，但：

- SSH 输入没有明显卡顿；
- 网站请求可以稳定完成；
- 下载和上传没有周期性中断；
- MTR 最后一跳没有持续丢包；

那么问题可能只是 ICMP 被限速或降优先级。Ping 适合观察趋势，不适合单独作为服务质量的全部依据。

## 如何测试搬瓦工丢包

### Linux 或 macOS：使用 ping

先测试本地到 VPS 的基本连通性：

bash
ping -c 100 YOUR_SERVER_IP


重点记录：

- 丢包率；
- 平均延迟；
- 最大延迟；
- 延迟是否突然跳高。

如果使用的是 macOS，命令格式基本相同。Windows 可以使用：

powershell
ping -n 100 YOUR_SERVER_IP


测试时尽量避免同时运行大型下载、云盘同步或视频上传。否则本地带宽被占满，结果会混入家庭网络拥塞。

### Linux：使用 MTR

安装工具：

bash
sudo apt update
sudo apt install mtr


运行报告模式：

bash
mtr -rwzc 100 YOUR_SERVER_IP


参数含义：

- `-r`：生成报告后退出；
- `-w`：使用较宽的输出格式；
- `-z`：显示 AS 信息；
- `-c 100`：发送 100 个测试包。

如果需要观察较长时间，可以把测试次数增加到 300：

bash
mtr -rwzc 300 YOUR_SERVER_IP


Windows 用户可以使用 WinMTR。测试完成后，重点查看最后一跳以及从哪一跳开始出现持续性异常。

### 测试去程和回程

本地到 VPS 的 MTR 只能看到一个方向。互联网线路通常存在去程和回程不对称的情况，去程走一条线路，回程可能经过另一家运营商。

因此，遇到搬瓦工丢包时，建议同时收集：

- 本地电脑到 VPS 的 MTR；
- VPS 到本地网络或公共目标的 MTR；
- VPS 到中国电信、联通、移动网络测试点的路由；
- 不同时间段的结果。

服务器端可以执行：

bash
mtr -rwzc 100 YOUR_LOCAL_TEST_TARGET


如果不知道本地公网地址，可以先使用多个公开测试目标进行对比，但不要因为某一个公共 IP 丢包，就认定搬瓦工整条线路都有问题。

## 线路差异为什么会影响搬瓦工丢包

搬瓦工官方将中国方向的网络分为不同类型。普通 AS4134 ChinaNet 成本较低，但高峰期更容易遇到拥堵；CN2 GT 的定位高于普通线路，不过官方也说明它在部分时期同样可能出现拥堵；CN2 GIA 和 CTGNet 则更偏向稳定性和中国方向的高质量连接。

简单理解：

| 网络类型 | 适合场景 | 丢包风险判断 |
| --- | --- | --- |
| 普通国际线路 | 海外网站、开发测试、低成本项目 | 中国方向晚高峰波动可能更明显 |
| CN2 GT | 对延迟有一定要求的普通业务 | 表现取决于具体机房和时段 |
| CN2 GIA | 中国用户访问、远程办公、网站和接口 | 通常更适合对稳定性敏感的业务 |
| CTGNet | 中国电信方向的高质量连接 | 需要结合实际运营商和机房测试 |
| CMIN2、China Unicom Premium | 中国移动、联通方向的优化连接 | 三网表现可能不同，需要分运营商验证 |

搬瓦工的 USCA_9 洛杉矶机房官方页面显示，中国方向会使用中国电信 CN2 GIA、中国移动 CMIN2 和中国联通 Premium 等网络，并提供多个数据中心之间的迁移能力。

这也是为什么同一家服务商、同一地区的两台 VPS，实际访问体验可能不同。决定丢包的因素不只有 CPU 和内存，机房、上游线路、运营商和时间段同样重要。

## 哪个套餐更适合排查丢包问题

### 只想测试线路：1GB 套餐够用

如果用途是：

- 部署测试站；
- 跑基础监控；
- 测试 Ping、MTR 和下载速度；
- 搭建轻量级开发环境；
- 验证中国方向访问质量；

1GB 配置已经足够。排查丢包时，关键是线路和机房，不是内存大小。直接购买高配套餐来测试网络，容易把预算花在用不到的计算资源上。

### 运行个人网站或 API：2GB 到 4GB

如果 VPS 还要运行 Nginx、数据库、缓存和应用服务，2GB 起步更稳妥。4GB 适合访问量稍高、需要运行多个进程或使用 Docker 的场景。

但要区分两类问题：

- 页面生成慢、CPU 长时间满载，属于资源或程序问题；
- 页面偶尔打不开、TCP 连接中断、MTR 最后一跳持续丢包，才更像网络问题。

不要把这两类问题混在一起。升级内存只能解决第一类中的一部分情况。

### 多服务或生产环境：8GB 及以上

8GB、16GB 及以上套餐适合运行多个站点、数据库、容器或较重的业务。它们提供更多 CPU、存储和流量额度，但价格差距也会明显增加。

如果你的主要目标只是减少搬瓦工丢包，优先确认以下事项：

1. 是否选择了面向中国方向优化的机房；
2. 三大运营商是否都需要覆盖；
3. 丢包是否只发生在某个时段；
4. 是否是单一 IP 或单一上游的问题；
5. 是否需要迁移到另一个数据中心。

配置升级应该服务于业务负载，而不是被当成线路优化工具。

## 已经出现丢包，应该怎么处理

### 第一步：确认本地网络

先关闭 Wi-Fi，改用网线或手机热点测试一次。如果热点网络明显正常，而家庭宽带丢包严重，问题可能在本地路由器、宽带线路或运营商出口。

也可以分别测试：

bash
ping -c 100 YOUR_SERVER_IP
mtr -rwzc 100 YOUR_SERVER_IP


记录测试时间和使用的网络运营商。

### 第二步：检查 VPS 资源

在服务器上执行：

bash
top
free -h
df -h
uptime


重点看：

- CPU 是否持续满载；
- 内存是否不足；
- 是否频繁使用 Swap；
- 磁盘是否已满；
- 系统负载是否长期高于 CPU 核数。

如果系统资源已经耗尽，应用层超时可能被误认为网络丢包。

### 第三步：更换机房而不是盲目升配

搬瓦工官方页面说明，VPS 可以通过 KiwiVM 控制面板执行数据中心迁移。迁移后通常会更换 IP，因此需要提前处理 DNS、白名单、防火墙和服务配置。

适合迁移的情况包括：

- 丢包持续数小时或数天；
- 最后一跳持续丢包；
- 不同本地网络测试结果相近；
- 只有当前机房异常；
- 更换时间段后问题仍然存在。

迁移前应备份数据库、配置文件和证书。不要把迁移当成百分之百有效的修复手段，因为不同运营商到新机房的路径仍可能发生变化。

### 第四步：联系官方支持

提交工单时，最好一次提供完整信息：

- VPS IP；
- 所在机房；
- 问题开始时间；
- 本地运营商和城市；
- Ping 结果；
- MTR 结果；
- 是否只在晚高峰发生；
- 是否影响 SSH、HTTP 或其他具体服务。

只写一句“我的 VPS 丢包，请处理”，通常很难让技术支持快速判断。带有时间范围和最后一跳结果的报告更有用。

购买搬瓦工之前，可以按这个顺序判断：

1. 明确用户主要来自哪家运营商；
2. 优先查看目标机房的测试 IP 或实际路由；
3. 分别在白天和晚高峰测试；

7. 结账前重新确认库存、价格、计费周期和可选机房。

如果你只是想要一台便宜 VPS，Basic KVM 可以作为低成本起点。如果主要问题是中国方向访问时的丢包、延迟和晚高峰稳定性，USCA_9 E-Commerce 系列更值得优先测试。当前链接对应洛杉矶 USCA_9，官方资料显示该机房配置了面向中国电信、移动和联通的多种网络连接。

## 最后判断：什么样的丢包才需要担心

可以用下面这条标准快速判断：

> 中间节点丢包不一定有问题；最终节点持续丢包，并且实际业务同时出现卡顿、超时或断连，才需要认真处理。

如果只是某一跳偶尔显示高 Loss，而最后一跳正常、SSH 和网站访问也没有异常，不建议立刻换套餐。

如果最后一跳持续丢包，且不同网络、不同时间测试都能复现，那么优先排查本地网络、运营商出口、机房和线路，再考虑迁移或更换方案。对于中国方向业务，选对机房通常比单纯增加内存更重要。
